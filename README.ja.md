## ツール一覧

| ツール | 用途 | 主な機能 |
| :--- | :--- | :--- |
| ♫ **音声結合** | 複数のWAVを1つにまとめる | ファイル名の自然順ソート、1〜2秒の無音挿入、元のサンプルデータを維持 |
| ⏱ **BPM計算ツール** | テンポの検出と補正 | 6帯域でのBPM検出、倍率補正、目標範囲への変換、タップテンポ |
| ¥ **ミックス料金計算機** | 有効なボーカル時間から見積もる | メインとハーモニーの個別計算、複数ファイル、定額料金、端数切り捨て |

### ♫ 音声結合

WAVファイルをドラッグすると、ファイル名順に並べ、クリップ間に無音を挿入して、1つのWAVとして書き出します。

- **自然順ソート：** `clip 2.wav` は `clip 10.wav` より前に並びます。
- **無音の長さを調整：** 1〜2秒の範囲で設定でき、1 / 1.5 / 2秒のプリセットもあります。先頭と末尾に余分な無音は追加しません。
- **サンプルデータを維持：** リサンプリングや再量子化を行わず、元のサンプルレート、ビット深度、チャンネル数、符号化方式を保ちます。
- **形式を検証：** サンプルレート、ビット深度、チャンネル構成、符号化方式が一致しない場合は、理由を表示して結合を停止します。
- **保存と試聴：** 出力名を変更してWAVを保存できます。ブラウザーが対応していれば試聴も可能です。

一般的なPCM / IEEE Float WAVに対応し、RIFFのサイズ上限を超える出力にはRF64を使用します。音声サンプルと必要な形式情報は維持しますが、アートワーク、マーカー、BWFの説明、タイムコードなどの付加情報は結合しません。RF64の再生には対応ソフトウェアが必要です。

### ⏱ BPM計算ツール

音声をドラッグしてBPMを自動検出するほか、検出値を手入力したり、ボタンやスペースキーでテンポを測定したりできます。

- **倍率補正：** `÷ 2`、`× 2`、`× 2/3`、`× 3/2` を適用し、ハーフタイム、ダブルタイム、1.5倍の検出差を補正します。
- **範囲変換：** 下限 `L` を設定し、正のBPMを `[L, 2L)` に変換します。
- **タップテンポ：** 最近のタップ間隔を平均します。長く間隔が空くと、新しい測定を開始します。
- **コピー：** 変換後のBPMをクリップボードへコピーします。
- **進捗とキャンセル：** 全曲解析の進捗を確認し、必要に応じて中止できます。

入力形式はブラウザーのデコード機能に依存し、MP3、WAV、M4A、FLAC、OGGなどを利用できます。上限は1ファイル250 MBです。音声を48 kHzでデコードし、第1チャンネルだけを6組の4次Butterworthローパス・ハイパス・バンドパスフィルターに通します。重なりのない1024サンプルのフレームごとに平均絶対振幅の正の差分を求め、全曲のHann窓を適用し、60〜240の整数BPM候補に対する6帯域の相関振幅を合計します。

条件を満たす局所ピークのうち最高スコアを採用し、同点なら小さいBPMを選びます。境界の60と240は選択しないため、結果は61〜239の整数です。無音、有効なピークがない場合、完全なフレームが2つ未満の場合は **BPM不明** と表示し、前回の検出値を消去します。ゼロで代用しません。末尾の1024サンプル未満の部分は解析対象外です。180秒で打ち切らず全曲を解析し、左右チャンネルを混合しません。目標範囲への変換と倍率補正は別の操作で、検出器の候補選択には影響しません。

デコードとリサンプリングはWeb Audioを使って端末内で行い、FFmpegは使用しません。数値結果がFFmpegとビット単位で一致することは保証しません。解析用の共通ゲインは約−12 dBFSのピークを目標としますが、元の音声ファイルを変更・書き出しすることはありません。第1チャンネルのリズムが弱い曲、テンポが変化する曲、ごく短い音声では、適切な結果が得られないことがあります。拍が明瞭で10秒以上の音声を推奨します。試聴やタップテンポでも確認してください。

### ¥ ミックス料金計算機

メインボーカルとハーモニーのドライ音声を別々に追加します。複数ファイルの選択、ドラッグ＆ドロップ、追加読み込みに対応しています。無音を除いた有効時間を合計し、時間欄へ自動入力して見積もりを計算します。

| 項目 | 料金ルール |
| :--- | :--- |
| メインボーカル | **1分あたり30人民元（CNY）** |
| ハーモニー | **1分あたり20人民元（CNY）** |
| メインの定額料金 | 有効時間がある場合、時間料金が**70元以上なら70元**、**20元未満なら20元**を自動選択。手動で変更可能 |
| 合計金額の端数処理 | 必要に応じて**5元単位で切り捨て** |

デコード後のメモリー上で、各ファイルのピークを **−6 dBFS** に正規化します。同一ファイル内の全チャンネルには共通のゲインを使います。既定の **−60 dBFS** を基準に有効な音を測定します。しきい値を調整したり、`1:30` や `1:30.25` のように課金時間を編集したりできます。元のファイルは変更しません。

同じ区分では、各ファイルの有効時間をそれぞれ加算します。別トラックで歌唱時間が重なっていても個別に計上しますが、1つのステレオファイルを2チャンネル分として二重計上することはありません。音量に基づく推定であり、ボーカルを分類するモデルではありません。伴奏、息、ノイズが含まれる場合があるため、ドライボーカルを使い、結果を確認してください。

検出と計算の詳細は[料金計算機の詳細ドキュメント（中国語）](cashier/README.md)を参照してください。

## 使い方

### Web版

[takoserver.top](https://takoserver.top/) を開くだけで利用できます。インストールは不要です。

### ローカル開発とビルド

Node.jsとnpmが必要です。宣言されているバージョン範囲は [package.json](package.json) を確認し、サポート期間内でセキュリティ修正済みのバージョンを使ってください。リポジトリのルートで実行します。

```sh
npm ci
npm run dev
```

ターミナルに表示されるローカルURLを開きます。ソースの `index.html` はViteのエントリーポイントなので、開発サーバー経由でアクセスしてください。

```sh
npm run build
npm run preview
```

ビルドでは次の2種類を生成します。

- **`dist/`：** 単一のアプリとして静的配信する版です。ツールのURLは `#/audiojoin`、`#/bpmcalc`、`#/cashier` です。従来のURLは対応する画面へ転送されます。`CNAME` も自動コピーされます。公開時は `dist/` の内容を配置してください。
- **`dist/offline/index.html`：** React、全ツール、JavaScript、スタイルを埋め込んだ単一HTMLです。直接開くことができ、別の場所へコピーしても追加ファイルやネットワーク接続なしでツールを切り替えられます。

**音声はブラウザー内で処理し、サーバーへアップロードしません。** オフライン版はCDNやネットワーク接続を必要としません。開発用依存関係が必要なのは、インストール・開発・ビルド時だけです。

### GitHub Pages

公開先は [takoserver.top](https://takoserver.top/) です。[Pagesワークフロー](.github/workflows/pages.yml)は、プルリクエストでコード・テスト・ビルドを検証し、`main` の更新時に `dist/` を公開します。プルリクエストの内容は本番へ公開しません。Actionsから手動で公開することもできます。

**Settings → Pages** のSourceには **GitHub Actions** を指定します。カスタムドメイン用の `CNAME` をコピーし、`.nojekyll` を生成します。リソースのパスはPagesのパス接頭辞に合わせるため、独自ドメインのルートとリポジトリのサブディレクトリーに対応します。Hashルーティングを使い、ツールへの直接アクセスや再読み込みにサーバー側のルーティング設定は不要です。

### Windowsデスクトップ版

```sh
npm run build:desktop
```

Windowsで実行すると、`outputs/audiojoin/` に起動プログラムとオフラインWeb版のZIPを生成します。起動プログラムは同じReactアプリをブラウザーのアプリウィンドウで開きます。[デスクトップ版の説明（中国語）](audiojoin/使用说明.txt)も参照してください。

### 言語と操作

アプリは **英語・日本語・簡体字中国語** に対応し、各画面上部で切り替えられます。このREADME上部のリンクはドキュメントの言語を切り替えるもので、アプリには別の言語選択があります。

- ブラウザーの保存機能が利用できる場合、言語の選択を記憶します。
- 言語を変更しても、ファイル、入力、手動の料金設定、結果を維持します。状態表示やアクセシビリティラベルも翻訳されます。
- すべての言語で人民元による同じ料金ルールを使い、通貨換算はしません。
- モバイル表示と、システムの「視差効果を減らす」設定に対応しています。
- カードや共通ナビゲーションで、再読み込みせずにツールを切り替えられます。ブラウザーの戻る・進むと、ツールへの直接リンクも利用できます。
- ファイル、入力、見積もり、出力結果は現在のセッション中保持します。切り替え後も解析は継続します。音声結合から離れると試聴を一時停止し、ショートカットとドロップは現在のツールにだけ作用します。アプリを閉じるか再読み込みするとセッションの内容を消去します。

右上のGitHub Starラベルはこのリポジトリにリンクし、GitHubの公開APIからStar数を取得します。画面が表示されている間は毎分更新し、フォーカス復帰や再接続時にも取得間隔を守って確認します。失敗やレート制限時は再試行を遅らせて前回の値を保持し、初回に取得できない場合は `—` と表示します。単一HTMLのオフライン版ではこのリクエストを送りません。

## 開発と保守

**React 19、Vite 6、Tailwind CSS 4、Motion for React** を使用しています。ナビゲーション、ドロップ領域、状態表示、ファイル一覧、数値アニメーションを共通コンポーネント化しています。言語はReact Contextで管理し、テンポ検出・時間解析・料金計算・WAV処理は描画から分離しています。

Tailwindのテーマは `src/styles.css`、共通のユーティリティークラスは `src/ui/styles.js` にまとめています。Viteプラグインでローカルにコンパイルし、同じCSSをオフライン版へ埋め込みます。

開発時はReact Strict Modeを有効にしています。解析キューは純粋なreducerによる不変更新を使い、非同期処理やファイルはrefsで管理します。イベント購読、タイマー、処理中のタスクは副作用の終了時にクリーンアップします。Hashナビゲーションは `useSyncExternalStore` で購読し、言語Contextの値と翻訳コールバックも安定させています。ESLintでHooks、依存関係、描画の純粋性、Fast Refreshを検査し、Prettierで書式を統一します。

Motionはナビゲーション、画面切り替え、カード、ファイル一覧、数値の変化に使用しています。`MotionConfig reducedMotion="user"` とCSSメディアクエリーでシステム設定を尊重します。各ツールは初回アクセス時に読み込み、その後は状態を維持します。静的ホスティングにサーバー側のフォールバック設定は不要です。

```text
music_tools/
├── src/
│   ├── main.jsx               # Strict Modeのエントリーポイント
│   ├── App.jsx                # ツールナビゲーションとセッション状態
│   ├── navigation.js          # Hash購読と現在のツールのContext
│   ├── components.jsx         # 共通ナビゲーション、ドロップ、アニメーション
│   ├── i18n.js                # 言語Contextと翻訳Hooks
│   ├── providers/             # 言語状態のProvider
│   ├── styles.css             # Tailwindテーマと基本スタイル
│   ├── ui/                    # 共通のTailwindユーティリティー
│   ├── pages/                 # ホーム、WAV結合、BPM、料金計算
│   ├── hooks/                 # 音声解析とStar更新の状態
│   └── lib/                   # テンポ検出、時間解析、料金計算
├── audiojoin/                 # 旧URLの転送、WAVエンジン、デスクトップ版
├── bpmcalc/                   # 旧URLの転送
├── cashier/                   # 旧URLの転送、ボーカル解析、翻訳
├── shared/                    # 翻訳辞書と言語設定
├── scripts/build-offline.mjs   # 単一HTMLの生成
├── tests/                     # アルゴリズムとブラウザーの回帰テスト
├── README.md                  # 英語版（既定）
├── README.ja.md               # 日本語版
├── README.zh-CN.md            # 簡体字中国語版
├── vite.config.mjs            # 静的アプリのビルド設定
├── CNAME                      # カスタムドメイン
└── LICENSE                    # GNU AGPLv3
```

ホーム、BPM、音声結合の文言は `shared/translations.js`、料金計算の文言は `cashier/translations.js` で管理します。言語間でプレースホルダーを一致させてください。WAVとボーカル解析エンジンはブラウザー / CommonJSの両方に対応し、独立したテストが可能です。画面の状態と描画はReactで管理します。

### 検証

依存関係のインストール後、リポジトリのルートで実行します。

```sh
npm test
npm run lint
npm run format:check
npm run build
npm run test:e2e
npm run test:e2e:dev
```

ブラウザーテスト前にビルドが必要です。`test:e2e` は本番用ファイル、`test:e2e:dev` はStrict Modeの開発サーバーで同じ操作を検証します。Windowsではインストール済みのEdgeを自動使用します。ほかの環境では `npx playwright install chromium` を実行するか、`BROWSER_PATH` に対応ブラウザーを指定してください。

ボーカルの有効時間、整数BPMと境界ルール、料金、WAVのサンプルデータ保持、形式検証、翻訳、ドラッグ＆ドロップ、解析中の追加、キャンセル、クリップボード、モバイル表示、動きを減らす設定、`file://` でのオフライン利用、状態保持、バックグラウンド処理、イベントの分離、旧URLの転送、履歴操作を検証します。スクリーンショットは `tmp/react-qa/` に出力します。
